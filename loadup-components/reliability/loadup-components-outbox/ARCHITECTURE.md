# Outbox Architecture

## 职责与结构

单一 jar 提供 Spring JDBC 事务事件发布及 MySQL 本地投递。选用单实现结构，不预建存储 SPI、消息队列 binder 或第二套任务引擎。数据库队列所需的 SQL 与事务封装集中在 `JdbcOutboxRepository`，不依赖业务模块和 MyBatis-Flex 自动填充。

| 类型 | 职责 |
|---|---|
| OutboxTemplate / OutboxMessage | 发布与租户内运营访问 |
| JdbcOutboxRepository | 数据库存储、短事务领取、带凭证确认 |
| OutboxHandler | 按事件类型执行业务工作 |
| OutboxDispatcher | 处理器选择、异常归类、上下文与观测 |
| OutboxWorker | 专属单线程轮询与应用生命周期 |
| OutboxInbox | 本地消费去重与业务事务绑定 |

## 事务边界

```text
业务事务：业务写入 + publish INSERT → 同时提交或回滚
领取事务：锁定一条到期记录 → 更新凭证 / 次数 / 租约 → 提交
事务外：执行处理器
确认事务：按事件 ID + 状态 + 凭证 + 有效租约更新结果
```

发布检查真实、可写事务及绑定数据源的非自动提交连接。应用的事务管理器负责业务事务；仓库内部使用独立 JDBC 事务管理器和 `REQUIRES_NEW`，不覆盖应用默认事务管理器。

工作线程启动后第一轮延迟一个轮询间隔，迁移应先于应用生命周期启动完成。组件只附带 Flyway 迁移，部署工程控制执行与升级；首版要求 MySQL 8+，不宣称跨数据库兼容。

## 状态与租约

```text
PENDING → PROCESSING → SUCCEEDED
                  └→ PENDING（退避）或 FAILED（耗尽）
PROCESSING（租约过期）→ 再领取或 FAILED
FAILED → PENDING（有记录的人工重放）
```

每次领取生成新的 UUID 凭证。租约过期后的旧执行者不能确认或改写新执行者状态。数据库 `UTC_TIMESTAMP(6)` 统一计算就绪时间和租约，避免不同工作节点时钟差异。成功确认时租约必须有效。

一次只领取一条，再执行处理器，避免批量预领取导致尚未执行的事件租约已过期。`batch-size` 限制一轮处理数量，单实例串行执行；规模扩展首先使用多工作节点。过期恢复也消耗尝试次数，防止进程不断退出而无限重试。

不提供租约续期或强制终止任意 Java 处理器。处理器负责合理的网络超时，任务时长应低于租约；进程退出或关闭后由租约恢复未确认事件。组件无法阻止过期执行者继续产生外部副作用，下游幂等仍然必要。

## 幂等与事件版本

事件 ID 标识一次发布，业务 ID 是关联字段，不是发布唯一键。业务层先通过请求幂等和业务约束保证不会重复创建语义相同的事件。

Inbox 使用 `(tenant_id, consumer_id, event_id)` 唯一索引，必须在可写业务事务内插入，并与消费者数据库写入共同提交。回调失败标记当前事务回滚。Inbox 不能为事务外副作用提供恰好一次保证。

不保证全局、业务 ID 或类型内顺序；需要顺序的投影使用业务版本拒绝旧事件，或由业务组织顺序处理。载荷版本由处理器明确支持，未知版本应抛异常并进入有限失败流程。

## 权限、观测与保留

运营访问强制指定租户；组件不根据未经验证的请求头推断权限。管理端授权和人工重放权限属于消费工程。类型注册在启动时检测重复；日志仅包含事件 ID、尝试次数和异常类型。

处理 Observation 为独立后台操作，原 traceId 保存在 `originTraceId` 用于关联；不把任意 traceId 字符串注入真实 Span 上下文。线程租户和 MDC 在处理结束时恢复。

表具有标准 ID、租户、时间和 deleted 字段，但队列与 Inbox 不使用通用逻辑删除改变投递或唯一语义。重放历史独立保存。自动归档尚未实现；Inbox 保留期限须覆盖业务允许的重放窗口，超过期限的事件不得无约束重放。

首版只有本地处理器；未来接入消息队列时，投递确认表示 broker 接收，而最终消费者需自己实现 Inbox。不得把 broker 确认误认为最终业务完成。
