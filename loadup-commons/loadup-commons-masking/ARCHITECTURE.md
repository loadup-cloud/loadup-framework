# LoadUp Common Masking 架构

## 职责

以静态、无状态规则实现展示脱敏；不改写业务对象，不管理用户身份、密钥或配置中心。接口只有 `Masking`、`MaskType` 和 `@Masked`，避免脱敏策略与业务权限混杂。

## 依赖方向

```text
commons-masking（纯 Java）
    ↑                       ↑
webmvc Jackson 3 适配        日志/导出显式调用
    ↑
业务输出 DTO 声明 @Masked
```

commons 不依赖 Spring、Jackson、KMS 或业务模块。规则对 Unicode 码点计数，避免拆开代理对。返回新字符串，实体、存储原值不变；隐藏操作不可逆，无法通过脱敏值还原原文。

## 失败语义

预定义类型发现短值、不合法格式或控制字符时全隐藏；null 和空字符串保留。CUSTOM 的每端保留长度只能在 0–32 之间，错误规则抛异常。响应适配器对错误注解类型及长度直接拒绝序列化，不回退到原值。

## 扩展边界

新增固定规则时增加枚举及测试；独立业务规则可在输出模型中预先构造展示值。首版不设计全局权限线程变量、自动敏感字段推断、可配置表达式引擎或正则日志拦截器。展示脱敏、数据库加密、访问授权是不同边界：KMS 的远程调用不能放入逐字段序列化路径。

## 验证

`MaskingTest` 覆盖常用类型、短值、控制字符、Unicode、空值和错误保留长度。HTTP 层隔离与嵌套序列化用例位于 WebMVC 模块。
